# ADR-0006: Arabic-first i18n with RTL

- Status: Accepted
- Date: 2026-11-07

## Context

Most users in Egypt prefer Arabic. Retrofitting RTL and Arabic content later is expensive: layouts, icons, number and date formats, and search all change.

## Decision

- Locales `ar` (default) and `en`, in the URL (`/ar/...`, `/en/...`) for SEO, using `next-intl`.
- `<html dir="rtl">` for Arabic; CSS uses logical properties only (`ms-`, `me-`, `ps-`, `pe-`, `start`, `end` in Tailwind). No `left`/`right` utilities.
- User-generated content (titles, descriptions) is stored once in the language the user wrote it, with the language detected and stored; category and system content is stored in both languages.
- Numbers and dates are formatted with `Intl` per locale; prices use Western digits by default with an option for Arabic-Indic digits.
- Search indexes Arabic with normalization (alef variants, taa marbuta, diacritics removed).

## Consequences

- Every UI change is checked in both directions; a CI visual check can come later.
- Translations are part of a feature's definition of done.
